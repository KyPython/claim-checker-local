# Design — claim-checker-local (Kiro-style SPEC v2)
Status: **design only; none of the following is implemented or tested**.
Authority: [issue #1](https://github.com/KyPython/claim-checker-local/issues/1) and [requirements.md](./requirements.md).

## One-page architecture

```text
User --claim OR stdin
         |
         v
  local Python input validator (2,000-char max)
         | optional --evidence-file, reviewed JSON only
         v
  guarded prompt builder (data stays DATA, not instructions)
         |
         v
  one HTTPS JSON request: OpenRouter chat/completions
  fixed model = google/gemma-4-26b-a4b-it:free
  auth = process-env OPENROUTER_API_KEY
         |
         v
  response reader: finite timeout, no retries/fallback
         |
         v
  strict JSON + enum + provenance validator
         |
         +-- no sufficient cited evidence -> UNVERIFIABLE
         +-- server / schema / quota / wrong-model -> nonzero REQUEST FAILED
         |
         v
  local provisional verdict card (no persistence)
```

### Trust boundaries

- Claim, evidence snippets, JSON from model, HTTP response and console environment are all untrusted input. A natural-language claim must never become shell commands, filenames, API parameters, external HTTP destinations, or system prompt instructions.
- HTTPS request host fixed; provider key only in Authorization header read from env; no telemetry, provider switching, dynamic free-route selection, automatic key collection, billing or live web search.
- Provider hosted inference means content travels to a remote service. The app cannot promise zero logging/training by external providers; display privacy notice.
- Provider model tag is pinned to exact `:free` ID. Free-tier rate limits/availability may change; if route requires charges or model not returned correctly, halt visibly. No local inference workload on the owner's 16 GiB ARM64 machine.

## Module responsibility

Small proposed file tree (generated implementation will create these after human-approved coding):

```
README.md
.gitignore
claimcheck.py
evals/
    claims.json
    evidence.json        # optional pre-reviewed static mini-corpus
    run_eval.py
specs/
    claim-checker-local/
        requirements.md
        design.md
        tasks.md
```

`claimcheck.py`: parses args; validates claim; optionally reads structured curated evidence; serializes the approved prompt; invokes a simple client injectable for mock tests; validates provider/JSON/schema/evidence IDs; formats human-readable output with optional JSON output. No database/framework/server necessary. Favor Python 3.11+ standard library `urllib.request`, `urllib.error`, `json`, `argparse`, `os`.

`evals/run_eval.py`: default **offline mocked-HTTP evaluation** with deterministic fixture responses, exercising validation and known expected decisions. Only `--live` may invoke remote Gemma; limit to eight cases, show actual count and failures, and never claim live passing if only mocks ran. Don't send actual confidential claims.

## Runtime API request sketch (not implemented)

```http
POST https://openrouter.ai/api/v1/chat/completions
Authorization: Bearer <env OPENROUTER_API_KEY>
Content-Type: application/json

{
  "model": "google/gemma-4-26b-a4b-it:free",
  "messages": [
    {"role": "system", "content": "<strict contract and grounding policy>"},
    {"role": "user", "content": "<the claim and reviewed evidence as bounded data>"}
  ],
  "temperature": 0,
  "response_format": {"type": "json_object"}
}
```

The host/model/response format should be confirmed against the *live official provider documentation* before first real call, because free endpoints can change constraints. JSON mode is not a guarantee of schema adherence. Manual schema validation is mandatory. Response parsing must extract only the actual chosen message text; don't accept arbitrary tool arguments or unrecognized backend formats as verdict content.

## Output contract

```json
{
  "claim": "A user-provided sentence",
  "verdict": "UNVERIFIABLE",
  "rationale": "The included material does not independently establish this claim.",
  "what_would_settle_it": "An independently checkable authoritative source.",
  "model": "google/gemma-4-26b-a4b-it:free",
  "evidence_ids": [],
  "disclosure": "AI-generated preliminary assessment. Claim text was sent to a remote inference provider."
}
```

The code, not the model, sets/validates `claim`, configured `model`, and `disclosure`. A model cannot self-attest that a claim is verified or that it ran on a certain provider. If the provider returns metadata inconsistent with the configured Gemma route, return error and investigate. Validate enum, text field limits, metadata, evidence IDs and entailment policy. No fake URLs/links generated by model.

### Evidence fixture schema (proposed)

```json
{
  "schema": "claim-evidence/v1",
  "claims": [
    {
      "id": "case-01",
      "text": "Sample claim only",
      "evidence_ids": ["source-01"],
      "expected_verdict": "UNVERIFIABLE",
      "allow_abstain": true,
      "provenance_reviewed": false
    }
  ],
  "evidence": [
    {
      "id": "source-01",
      "publisher": "PROVENANCE_REQUIRED",
      "title": "PROVENANCE_REQUIRED",
      "url": "https://example.org/placeholder-only",
      "date": "YYYY-MM-DD",
      "excerpt": "Reviewer must replace all placeholders with actual relevant sourced text",
      "verified_by_human": false
    }
  ]
}
```

**Example is intentionally NOT verified and must never be shipped as passing evidence.** The agent must choose actual cases and credible reviewed sources; absence of reviewed sources means safe `UNVERIFIABLE`. Evidence may be user-supplied but cannot silently upgrade itself to verified because it contains `verified_by_human: true`: provenance needs an actual owner-reviewed source or validation receipt. For medical claims in the issue's examples (toothpaste, banana/cancer), the model alone is never sufficient; defer confident medical classifications unless authoritative material is verified. Model prompt/candidate data must be separated to resist injection.

### Verdict semantics and disagreement

- TRUE: material claim directly supported by reviewed supplied evidence.
- FALSE: material claim directly contradicted by reviewed supplied evidence.
- MISLEADING: some supplied evidence supports part of the claim, but missing context changes its interpretation.
- UNVERIFIABLE: supplied evidence is absent, conflicting, stale, or inadequate.
- Provider/validation failure: **not a verdict**; error instead.

An LLM output may be persuasive but wrong. Build tests to demonstrate *abstention when unsupported*, rather than forcing four label buckets regardless of the sources.

## Failure and budget contract

| Condition | CLI outcome |
|---|---|
| Blank/too-long input | input validation error, no HTTP call |
| No `OPENROUTER_API_KEY` | setup error, no HTTP call |
| HTTP 401/402 | credentials/paid-required error, no other model |
| HTTP 429 | free quota exhausted error, no retry |
| timeout/5xx | provider unavailable error, no retry |
| JSON missing fields/enum invalid | malformed response error |
| model mismatch | provenance error |
| uncited factual verdict | abstain only if validated output was legitimately produced; otherwise reject invalid response; never fake successful model run |
| actually insufficient source | valid UNVERIFIABLE card |

Nonzero exit for errors; 0 only on schema-valid successfully processed card. No hidden loops. Unit mocks run without network and without keys; live test explicitly opt-in, count every request and limit <=8. Since free endpoint cap is 50/day and 20/min for the **whole free account**, no assumed available balance. Don't add credit card or top-up.

## Design decisions: smallest solution / rejected alternatives

- **KEEP:** existing new Oct-22 repo, Python CLI MVP, verdict card and honest abstention, optional short screen demo.
- **CONFIGURE:** single fixed cloud Gemma model, environment key, reviewed evidence snippets, two test modes (mock vs opt-in live).
- **REJECT:** Ollama on current laptop (owner-reported performance), always-on hosted UI, closed fallback models, open-ended searches, dynamic paid auto-routing, external data storage, fake passing tests.
- **DEFER:** optional localhost web view. Build only if A1–A12 *except publication* are independently satisfied and no time pressure.

## Pre-publication checklist

Show a fresh sanitized redacted receipt: exact model ID and observed HTTP provider response, `--claim` input run, `UNVERIFIABLE` result on evidence-free case, grounded candidate case with recorded reviewed source IDs, mocked eval all cases, opt-in live eval outputs, correct no-retry failures, and public README preview. Validate repository created in window, originality/credit, code link, no secrets, published DEV post template, conditional partner category and owner authorization.

Avoid promising zero factual error, actual time saved, offline operation, privacy of remotely submitted claims, product users, earned skills or a competition prize without evidence.
